# Contributing to Allura

Thank you for helping improve Allura.

## Before You Start

1. Read the target repository's local instructions and governance files.
2. Confirm whether the repository is public, private, original, or upstream-derived.
3. State the intended change and the evidence that will prove it works.
4. Keep client data, credentials, and private operational details out of public artifacts.

## Pull Requests

Include:

- The problem and intended outcome
- Files and boundaries affected
- Validation commands and results
- Upstream attribution when work is reused
- Rendered evidence for visual changes
- Known risks and follow-up work

Do not add unsupported marketing metrics or present planned behavior as implemented.

## Provenance

When introducing upstream work, include its source URL, license, relevant commit or release, and a plain-language summary of Allura's changes.
